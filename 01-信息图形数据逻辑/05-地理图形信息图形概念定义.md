# 05｜地理图形信息图形：概念、数据与设计方法

> 研究层级：本知识库五种基础数据逻辑之一。结构与分析维度参考 [Infographic-Style-Repository](https://github.com/fengbaifan/Infographic-Style-Repository/tree/main/01-信息图形数据逻辑)，重新结合本库课堂和案例材料撰写。示例 CSV 为**抽象结构**，不冒充原图真实源数据。

## 概念定义
**空间位置、邻接、区域、距离、路线或分布是主导结构，地理参照不能被任意调整而不破坏作品信息。**

## A｜基本数据逻辑：什么数据结构是本质？
每项空间观测由 location_id 与经纬度、行政区域键、几何或路网节点定位；空间位置与统计变量应经稳定键关联，并注明 CRS/投影、统计地域范围。

### 主归属判定
**如果只是用地图做装饰而条目真正按时间组织，应归编年；引线连接比例圆和地图点只表身份对应，不等于资金流或行驶路线。**

## B｜借用的统计图形、统计和计算
空间计数、密度=count/area、区域比例、空间汇总、两点距离、路径距离与邻接；分级设色按规范分母；比例圆面积映射量值，线段只在有流动量字段时代表流量。

## C｜视觉编码：点、线、面、体、符号、颜色、文字
点=位置与数量符号；线=边界、轨迹、路线或仅定位引线；面=真实区域或按指标设色的面；体=三维地形或建筑示意而非精确比较；图标=地点身份；颜色=类别或量级需有图例；投影/比例尺与文字标注不可忽略。

编码顺序：**数据关系正确 → 计量精度和连接正确 → 感知分组清晰 → 视觉修饰**。任何元素都应声明是否承载数据，装饰性元素不默认承担数值。

## D｜数据／信息架构
**推荐原子字段：** `location_id,latitude,longitude,region_id,value,unit,period,geometry_ref,crs,source_id`

一行代表一个可稳定识别的最小实体或关系记录；一列只放一个属性；一个单元格只放一个值。跨表通过 ID 关联。示例结构如下：

```csv
location_id,latitude,longitude,value,unit
R01,40.71,-74.00,,USD
R02,34.05,-118.24,,USD
```

图中缺失数值、无法还原的坐标或作者计算方法必须明确标注为缺失或推断，不能补造。

## E｜视觉叙事架构
全局空间格局→主要区域/热点或路径→差异与局部观察→回到总体及空间口径。

信息架构（字段、键与关联）负责内容如何存放；视觉叙事（注意入口与阅读路径）负责读者如何获取和理解内容，两者不能互相代替。
