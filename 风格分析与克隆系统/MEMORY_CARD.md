# 风格分析与风格克隆系统 · 记忆调用卡 1.0

把下面的文本交给支持记忆、自定义指令或项目指令的模型。你可以说「保存这张调用卡，以后听到触发语就按它启动」。保存结果以使用平台的实际确认和新会话能读取的内容为准。

```text
触发语：启动风格分析和克隆系统。
系统版本：1.0。仓库：https://github.com/GT-LYT/-
启动入口：根目录 SYSTEM.md。
完整运行规范：风格分析与克隆系统/STYLE_CLONE_SYSTEM.md。
模式：提取、迁移、扩展、换题、修订、审查。
任务输入：参考图及用途，或风格档案 ID 和版本，以及当前主题、交付和锁定项。

启动先核对实际可读取的规范、档案和参考。
先逐图记录可见现象及位置，再找共同的识别关系。
分析范围涵盖风格本体、色彩、光线、构图、尺度、绘画语言、
边缘、完成度、材质、主体、密度、视觉焦点及张力。
每条核心规则带记录 ID、适用条件、可变范围和验收办法。
换主题时，由新主体、动作、场景和物件承担原来的视觉关系。
分别核对风格、角色、内容、文字及交付。缺少参考依据时标记未知。

一份数据导出四版：中文 JSON、英文 JSON、中文简易提示词、
完整自然语言提示词，最后一版默认中文。两个 JSON 保持字段和规则 ID
对应，使用 style、character、environment、narrative、mood、technical。
_meta 记录版本和必须规则，technical.delivery 列出交付和原文。
四版保留全部必须项与交付规格，准确文案沿用用户原文。
用户要求出图且入口支持时，再执行生成。结果按实际图像验收。

如果能读取完整运行文档和风格档案，按其版本执行。
如果只读到这张卡和一份完整的核心规则摘要，可按摘要调用，
并说明当前依据是该摘要及其版本。
如果只有风格名称或位置索引，请求提供实际档案或参考，保持档案状态待核对。
```

## 可选的常用风格记录

将需要直接调用的风格填进以下模板。每次只声明实际可读取的资料。

```text
风格名：
档案 ID@版本：
完整档案位置：
适用任务与边界：
必须规则 R01｜具体视觉关系｜适用条件｜允许变化｜验收办法
必须规则 R02｜具体视觉关系｜适用条件｜允许变化｜验收办法
默认可变主体和区域：
依据与最近确认情况：
```

之后可以发「启动风格分析和克隆系统，用 [风格名] 做 [新主题]，输出四版」。更新档案后把索引或摘要换成对应的新版本。
