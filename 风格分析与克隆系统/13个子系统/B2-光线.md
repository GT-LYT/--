# B2 · 光线子系统

## 目标

亮暗如何引导注意、塑造形体和空间？

## 输入

参考图、可见亮暗区域、目标场景。缺少图像或关键任务时标记 `pending`，不得填充虚构证据。

## 执行

1. 标出高光、暗部、反差和阴影。
2. 区分观察到的明暗与推断的物理光源。
3. 检验新主体是否能承接亮暗功能。

每条判断记录 `observation`、`inference`、`user_requirement` 或 `design_choice`，并标出参考 ID 与区域。用「可见特征 → 功能 → 可迁移关系 → 允许变化 → 验收」写可引用规则。

## 输出合同

写入统一 `style-profile.json` 的 `analysis`，`module` 固定为 `B2`，保留 `state`、`observations`；确有可复用关系时写入 `rules`，使用唯一规则 ID、证据、条件、优先级、依赖和检查方法。本子系统的专属结果为亮暗地图、光线规则、未知来源与适配要求。可单独调用，之后与其他系统的结果合并，避免覆盖现有规则。

## 换题与验收

光源类型可按主题变化，焦点的亮暗层级须可读。只在图像支持时写物理光向；缩略图核对主次亮度。实际生成图缺失时，图像验收状态为 `not_generated`。
